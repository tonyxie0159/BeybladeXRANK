# UI 規格

所有頁面以手機／平板優先，使用 Bootstrap responsive。重要裁判操作使用清楚的大按鈕；破壞性或不可逆操作需要明確確認，不把核心操作藏在 dropdown。

## 共用視覺與互動系統

- 全站使用同一深色高對比設計 token；Card、List、Form、Table、Alert、Pagination 不得退回白底預設樣式造成對比中斷。
- 頁面標題使用一致的 eyebrow、主標題、摘要與右側操作區；手機版操作區改為全寬觸控按鈕。
- 登入後手機版固定顯示首頁、對戰、賽事、戰績四個主要返回入口；完整功能仍可由頂部導覽到達。
- 頂部導覽需顯示目前區段，collapse 控制項的 target／id 必須一致，鍵盤使用者可跳到主要內容。
- 空清單需說明下一步並提供主要動作，不只顯示「沒有資料」。
- POST 送出後按鈕顯示「處理中」並避免重複點擊；Server 端 idempotency／concurrency 保護仍是獨立要求，不能以 Client 防連點取代。
- 表單只有在前端驗證通過且提交未取消時才鎖定；驗證失敗、Server 錯誤、`pageshow` 快取還原或返回頁面時立即恢復按鈕。
- 未包覆的資料表由共用腳本加上橫向捲動容器，手機版不可讓整個頁面水平溢出。
- 支援 `prefers-reduced-motion`，焦點需有高對比外框，Alert 補上適合的 status／alert 語意。

## 全域導覽

登入後提供：

- Home
- 比賽房間
- 快速對戰
- 對戰邀請／進行中的快速對戰
- 我的陀螺
- 我的戰績／對戰歷史
- 帳號設定
- 登出

待處理邀請、準備中及進行中的對戰必須有可發現的返回入口。使用者不需要保存 URL 或 BattleId。

右上角固定提供通知鈴鐺，且鈴鐺必須位於手機版可收合導覽之外，任何畫面寬度都保持可見。未讀時顯示驚嘆號及螢幕閱讀器可讀數量；邀請與待辦先顯示六秒浮動提示，可直接接受或前往處理。提示消失不等於已讀，拒絕、取消、棄權等破壞性操作只能在目標頁完成。

## Account

### Login／Register

- Account
- Password
- Register 另含 DisplayName
- 顯示 validation error，不回傳 PasswordHash 或透露其他帳號私密資料
- Account 與 DisplayName 都使用 trim、英文不分大小寫的唯一性規則

### Settings

- 只修改目前登入者 DisplayName。
- 修改後不改變 UserId、Account、歷史 Entry／Lineup Snapshot 或統計歸屬。

## Beyblade

- 列表顯示未軟刪除的目前使用者陀螺。
- 提供新增、改名、刪除。
- 快速／Tournament Lineup 頁提供「新增我的陀螺」、「刷新陀螺」及「刷新對戰狀態」。
- 歷史頁以 Snapshot 顯示當時名稱；戰績總覽可用同一 BeybladeId 的目前名稱作為標題。

## 快速對戰

### Create

- 選擇不同於自己的對手並送出站內邀請。
- 送出後導向邀請清單；接受前不顯示 Battle。

### Invitations／Active Battles

分區顯示：

- 收到的待處理邀請：接受／拒絕。
- 已送出的邀請：等待／撤回。
- 準備中的 Battle。
- 進行中、等待重排及已達勝利門檻的 Battle。

依 Battle 狀態導向 Setup、Reorder 或 Battle 畫面。SignalR 事件後立即同步及導向；重新連線、回到前景或手機解除休眠時重新核對 Server，低頻 polling 與手動刷新只作備援。

### Setup

1. 雙方各自選擇自己的三顆及順位。
2. 雙方都提交後同時公開。
3. 雙方確認，或提出每人每版至多一次的重新編輯請求。
4. 發起人指定 Side A 為 B Side（藍）或 X Side（紅）。
5. 發起人開始對戰。

私密階段只顯示登入者自己的 submission。Side 指定前不可開始；開始後不可返回賽前階段。

### Battle

上方固定清楚顯示：

- B Side／X Side 及藍／紅視覺。
- 實際玩家或隊伍名稱。
- B Side／X Side 累積比分與 ScoreToWin。
- 當前 Round、實際 Player 及雙方陀螺 Snapshot。
- 當前有效 fault count，顯示在計分板內對應玩家下方。

裁判操作：

- 轉停勝利 +1
- 擊飛勝利 +2
- 爆裂勝利 +2
- 極限勝利 +3
- 各實際玩家發射失誤
- 「對戰紀錄」、「判決修改」、「對戰處理」同列；棄權與快速對戰取消只在展開「對戰處理」後顯示

點擊勝利方式會立即在同一交易記錄結果並完成當局，不再顯示逐局確認按鈕。歷史紀錄與當前對局分區顯示；獨立對戰紀錄頁包含有效／失效局與修訂稽核，並提供回到比賽。完賽頁提供回到首頁，賽事對戰另提供返回賽事。

指定 B／X Side 後雙方留在準備頁；只有建立者正式開始並成功建立第一 Round 後，雙方才進入計分頁。對戰結算顯示勝利玩家／隊伍、B／X Side 最終比分、回到首頁、對戰紀錄，以及賽事對戰的返回賽事入口。

達門檻時顯示「已達勝利條件，請確認後按對戰結束」，禁止後續正常計分且不自動 Completed。

### Reorder

- 預設帶入目前順序。
- 玩家只能排列自己的首次鎖定陀螺。
- 雙方都提交前保持私密；完成後直接進入下一 Sequence。
- 雙方在狀態變更後立即進入重排／下一輪；提供返回比分與同步備援。

### Round Revision

- 顯示全部 Round 及有效／無效事件、失效原因。
- 可重新設定唯一 BattleResult。
- 修改原因必填。
- Tournament 勝方可能變更時，顯示下游影響與必要撤銷確認。
- 儲存後顯示重播後比分與 Battle／Match 狀態。

## Tournament

### List

只有登入者可查看；每頁 20 筆，由 Server 分頁、排序及篩選。

篩選：

- 全部、報名中、進行中、已結束、已取消
- 我參加的、我主辦的、等待我處理

等待邀請、補隊、出賽確認、Lineup、重排或裁判操作的項目優先，其餘依 UpdatedAtUtc 新到舊。每筆顯示名稱、主辦方、模式、報名方式、賽制、規則摘要、人數、備註摘要、目前關係與符合身份的操作按鈕。列表由 SignalR 即時提示並重新同步，低頻 polling 只作備援。

### Create

- 名稱、RuleSet、報名方式、賽制、目標 Entry 數、備註。
- Mode、TeamSize、BeybladesPerPlayer、ScoreToWin 與人數上限由 Server catalog 推導。
- 單人賽自動鎖定個人報名；團體賽只顯示「隊伍報名」與「由系統自動組隊」。
- 建立前預覽完整規則，不允許 Client 自訂被保護值。

### Details

所有使用者可見狀態與賽制使用集中式繁體中文標籤及語意色彩。時間只顯示建立、正式開始及完成。

- 報名中：有效個人／正式隊伍、剩餘名額、自己的編號與組隊狀態。
- 進行中／已結束：完整賽程只顯示順序、出戰隊伍、整合中文狀態／勝敗方／最終比分的對戰結果，不顯示內部 Round／Match 代碼；單淘汰／雙敗只在賽事完成後顯示正式名次與淘汰依據。循環／瑞士冠軍完全同分時顯示獨立「冠軍加賽」賽程，完成前標示目前排名而非正式排名。
- 已取消：取消原因／時間，以及取消前合法完成的 Match／Battle／比分。
- 未完成提交的 Lineup、Account、待處理邀請與未完成臨時隊伍不可公開。

一般觀眾可讀取已公開資料；只有主辦方與該 Match 參賽者可進入私密 Match workspace。詳情與當前 Match 透過 SignalR 即時提示狀態變更，重連同步與唯讀 polling 作備援。

### Registration／Team

- 個人報名、取消報名及主辦方重新開放報名。
- 主辦方以 DisplayName 模糊搜尋下拉選單邀請玩家；一個中文字起查、250ms 防抖、最多十筆，排除本人、已邀請與不符合資格者。表單只提交 UserId，Server 重新驗證權限與狀態。
- 整隊報名：建立臨時隊伍、邀請、回覆、正式報名、代表人轉讓及退出。
- 系統配隊：個人登記、主辦方產生完整隊伍、交換成員、等待補足及重新開放。
- Tournament-scoped 團體不可出現在永久社群 Team 清單，因為產品沒有永久 Team。

### Match Workspace

- 出賽接受／拒絕；主辦方可二次確認判定未到 Walkover 並填原因。
- 每位必要玩家私密選螺；團體代表人另排列本隊出戰者。
- 全部提交後公開並由必要玩家確認。
- 主辦方指定 B／X Side 並開始。
- 進行中導向共用 Battle 畫面。
- 可辦理棄權、Void／Reopen、查看已撤銷 Battle audit。

## Statistics

分區：

- 快速對戰
- Tournament 個人
- Tournament 團體隊伍結果
- Tournament 團體實際小局
- 我的陀螺
- 對手戰績／對手陀螺
- 對戰歷史

個人分項與陀螺列表都支援：

- 得分、失分、得失分差、勝率排序
- B Side 勝率、X Side 勝率排序
- 全部／B Side／X Side 篩選
- 規範允許的來源篩選

篩選與排序由 Server 重新聚合。歷史每筆顯示來源、比分、勝負及使用者當場 B／X Side；相容舊資料若沒有 Side 顯示「未記錄」，不得推測。

## 無障礙與操作安全

- 表單都有 label、validation summary 與文字狀態，不只依顏色傳達 B／X 或錯誤。
- 重要按鈕在觸控裝置有足夠尺寸與間距。
- 取消、棄權、未到判定、Void／Reopen 與會撤銷下游資料的 Revision 必須顯示影響範圍並二次確認。
- SignalR、重連同步及 polling 不得重送 POST 或自動執行狀態變更。
